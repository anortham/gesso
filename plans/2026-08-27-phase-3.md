# Phase 3 Setup app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development when subagent delegation is available. Fall back to razorback:executing-plans for single-task, tightly-sequential, or no-delegation runs. This plan is a new-session handoff; do not start until the user approves this file.

**Goal:** `gesso setup` launches a Kirigami window whose Theme, Defaults, and Install pages exec `gesso-*`. Agents is an empty state. `./test/all` stays green with no display.

**Architecture:** `bin/gesso-setup` launches the compiled app. Pages call `GessoCli.run(["theme","list"])` and friends. `gesso theme current` is a new tiny command so QML does not read `theme.name` itself. No catalog ids in QML.

**Tech Stack:** bash 5, Qt 6, Kirigami 6, CMake, TAP bash tests.

**Architecture Quality:**

- **Affected modules:** setup launcher, theme-current, `setup/` QML/C++, desktop file, setup-test suite.
- **Caller-facing interface:** `gesso setup`, `gesso theme current`.
- **Depth/locality check:** Mutation stays in existing CLI. App only execs and displays.
- **Test surface:** `./test/cli` launcher/help/current/QML grep. No GUI runner.
- **Seams/adapters:** CLI stdout lines. `GessoCli` is the process adapter.
- **Rejected shortcuts:** QML reading `apps.toml`. Hard-coded Firefox. Agent install in the GUI.
- **Architecture risk:** medium if pages grow a second installer. Keep argv lists as the only mutations.

## Global Constraints

- Spec: `plans/2026-08-27-phase-3-setup-design.md`.
- QML must not contain `firefox.desktop`, `org.mozilla.firefox`, `org.chromium.Chromium`, or `com.google.Chrome`.
- Agents page is empty state only. No `mise`. No agent ids.
- `./test/cli` must not need a display or `cmake`.
- `# gesso:summary=` on new `bin/gesso-*`. Shebang `#!/bin/bash`. Two-space indent.
- Do not wrap pkexec around commands that already elevate.
- Do not add `gesso commands --json`.

```bash
#!/bin/bash
set -euo pipefail
source "$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/.." && pwd)/lib.sh"
gesso_test_init

cur=$(gesso theme current)
[[ $cur == "unset" ]] || fail "theme current unset without state" "$cur"
pass "theme current unset without state"

export GESSO_THEME_HEADLESS=1
gesso theme set tokyo-night
cur=$(gesso theme current)
[[ $cur == "tokyo-night" ]] || fail "theme current after set" "$cur"
pass "theme current after set"

if gesso setup --help >/dev/null 2>&1; then
  :
else
  fail "gesso setup --help exits 0"
fi
help=$(gesso setup --help)
[[ $help == *Setup* ]] || fail "setup help mentions Setup" "$help"
pass "gesso setup --help exits 0"

if GESSO_SETUP_BIN=/no/such/gesso-setup gesso setup >/tmp/gesso-setup-missing 2>&1; then
  fail "missing setup binary exits non-zero"
fi
pass "missing setup binary exits non-zero"
```

Expected: FAIL missing DefaultsPage.

**Step 3: Write minimal implementation**

For kinds `browser`, `terminal`, `editor`: load ids via `gessoCli.run(["catalog-get","--kind", kind])`. Hidden commands are on PATH as `gesso-catalog-get`; `GessoCli` runs `gesso` the router. Router may not map `gesso catalog-get`. **Required:** `GessoCli` must exec the program name `gesso` for user commands (`theme`, `default`, `pkg`, `setup`) and exec `gesso-catalog-get` / `gesso-cmd-present` by binary name for hidden helpers.

Add `GessoCli.runCommand(program, args)` or pass a leading binary. Document in the page: `gessoCli.run(["default","browser", id])` vs `gessoCli.runBinary("gesso-catalog-get", ["--kind","browser"])`.

Do not hard-code ids. Set default: `gesso default browser <id>` etc. Refresh current after success. Show stderr on failure.
