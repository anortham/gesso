# Gesso product plan

Date: 2026-08-26

This is the project brief. It records what to build, what not to build, and the first shipping shape. It is not an implementation task list yet.

## Name

**Gesso.** Primer on a canvas. Fedora KDE is the canvas. This project paints a palette, default apps, and a coding-agent loop on top. It does not replace the canvas.

CLI: `gesso theme set tokyo-night`, `gesso default browser firefox`, `gesso agent`.

RPMs: `gesso` (CLI + templates + agent commands), `gesso-plasma` (Look-and-Feel + Setup app). `mise` is not a Fedora package, so there is no agents RPM; `gesso default agent` installs `mise` per user.

Installed data: `/usr/share/gesso/`. User overlays: `~/.config/gesso/`. Generated state: `~/.local/state/gesso/`.

Rename is cheap until the first COPR publish. Do not spend more time on the name.

## Problem

Omarchy's last mile is the part worth stealing:

- One `colors.toml` renders terminal, editor, browser, and desktop configs, then retints running apps.
- A Setup row that is not installed yet will install, then set the XDG default.
- Coding agents install with `mise` and launch with a "don't ask" flag.

Omarchy ships that loop as an Arch + Hyprland OS. The keyboard tiling session is the tax, not the sauce.

Gesso takes the loop onto Fedora KDE 44, mouse first.

## Host and distribution

**Host (v1):** Fedora KDE Plasma Desktop 44, mutable, `dnf`.

**Host (v2, same RPMs if the files stay under `$HOME` and `/usr/share`):** Aurora / Kinoite. Layer or brew/`mise` instead of host `dnf` for extra apps. Do not require this in v1.

**Distribution:** COPR RPMs. `dnf copr enable … && dnf install gesso-plasma`.

**Not a Fedora remix, spin, or bootc image in v1.** Aurora already is the opinionated Fedora KDE OS. Competing there means owning NVIDIA, Secure Boot, and Fedora rebases. An image that `FROM` Aurora and adds these RPMs is a later channel, not the product.

## What to steal from Omarchy

Keep the command-as-API idea. The Setup app, CLI, and any KRunner plugin all call the same `gesso-*` binaries.

Steal these behaviors, not the files wholesale:

- Theme staging: copy built-in theme, overlay user theme, render `default/themed/*.tpl`, atomic swap into `~/.local/state/gesso/current/theme`.
- Template placeholders: `{{ accent }}`, `_strip`, `_rgb`, `mix`.
- `post_theme` retint. v1 applies Plasma, Konsole, GTK prefer-dark/light, Kitty if present, and VS Code `workbench.colorCustomizations` when `~/.config/Code/User` exists. Ghostty, Foot, and browser chrome are later.
- Default-app loop: missing binary → install → `xdg-settings` / `xdg-terminal-exec` / editor state file → notification.
- Agent loop: `mise use -g`, write `~/.config/gesso/defaults/agent`, launch with the agent's skip-prompt flag.
- Menu-as-data later, if a second UI appears. v1 UI is the Setup app.

Omarchy references (read, do not vendor the repo):

- `docs/theming.md`, `bin/omarchy-theme-set`, `bin/omarchy-theme-set-templates`
- `bin/omarchy-default-browser`, `bin/omarchy-default-terminal`, `bin/omarchy-default-editor`
- `bin/omarchy-default-agent`, `bin/omarchy-agent`
- `docs/cli-router.md` for the spaced-command router

## What not to steal

- Hyprland, Quickshell as the desktop, Super+C universal clipboard, Limine, Snapper, ISO provisioning, pacman/AUR, `omarchy-settings` `/etc` clobber, the pacman update guard.
- Replacing plasmashell, Kickoff, or Klipper.
- Omarchy's name, themes as a 1:1 dump (start with a small first-party set; generate Plasma `.colors` from the same palette).

## Product surface (v1)

One Kirigami window, **Gesso Setup**, with four pages:

1. **Theme** — list built-in + user themes, Apply. No live preview in v1.
2. **Defaults** — Browser, Terminal, Editor. Each row: installed state, Set default. Missing → install via `dnf` and/or Flatpak, then set default.
3. **Agents** — Pi, OpenCode, Claude, Codex, Grok, Copilot, and the rest of the Omarchy set that `mise` can install. Unset until the user picks one. Launch button.
4. **Install** — catalog browsers, terminals, and editors. Rows dim when present. Not a replacement for Discover/Bazaar.

CLI is complete without the GUI. The app is a mouse front end.

## Architecture

```
gesso (CLI router)
  theme set|list|current|restore → templates + plasma-apply-colorscheme + retint
  default browser|terminal|editor|agent
  pkg add                    → dnf, then Flatpak fallback for listed apps
  agent | default agent
  setup                      → launches the Kirigami app

gesso-plasma
  /usr/share/gesso/themes/*/colors.toml
  generated or shipped .colors
  Look-and-Feel (wallpaper + color scheme; no custom SVG plasma theme in v1)
  gesso-setup (Kirigami)
```

Agent commands live in `gesso`. `mise` installs per user into `~/.local/bin/mise` on first `gesso default agent`. No RPM can Require `mise` on Fedora.

`theme install` and `pkg drop` are later. Do not treat them as v1.

State:

| Kind | Path |
|---|---|
| Built-in themes and templates | `/usr/share/gesso/` |
| User themes, hooks, template overrides | `~/.config/gesso/` |
| Generated current theme, editor default | `~/.local/state/gesso/` |
| Default agent | `~/.config/gesso/defaults/agent` |

Uninstall must leave the machine usable: restore Breeze / Fedora defaults if Gesso was the active color scheme, do not delete the user's `~/.config/gesso` unless they pass a purge flag.

## Package and command rules

- Commands start with `gesso-`. A router maps `gesso theme set` → `gesso-theme-set`.
- No `/etc` hijack. No bootloader, SDDM, kernel, or NVIDIA ownership.
- Theme files that Plasma and apps read at runtime go under `~/.local/share` and `~/.local/state`, so Aurora/Kinoite can use the same code.
- Installers try Fedora packages first, then Flathub ids from a single app catalog file (`data/apps.toml` or similar). Hard-code nothing in the Setup QML.
- Privilege: `pkexec`/`dnf` when there is no TTY; sudo when there is. Follow Omarchy's privilege split in spirit.

## Phased delivery

### Phase 0 — repo and CLI skeleton

Router, `gesso theme list` on one hand-written theme, tests that do not need Plasma.

### Phase 1 — theme engine

`colors.toml` → templates for Konsole, Kitty, VS Code, and a Plasma `.colors` file. `gesso theme set` applies the Plasma scheme and writes generated configs. GTK prefer-dark/light via `gsettings`. Ghostty, Foot, and browser chrome are later.

Success: switch theme, Plasma chrome and Konsole match, `gesso theme set` is idempotent.

### Phase 2 — defaults

Browser / terminal / editor catalog. Missing → install → set default. Fedora package names and Flatpak ids in the catalog.

Success: `gesso default browser firefox` on a machine without Firefox installs it and `xdg-settings` reports Firefox.

### Phase 3 — Setup app

Kirigami app, four pages, all actions shell out to the CLI. Mouse first. Keyboard still works because Kirigami.

Success: a new Fedora KDE user can theme, pick Firefox, pick Grok, without a terminal.

### Phase 4 — agents

Agent commands in the `gesso` RPM. `mise` installs per user (no RPM can Require it on Fedora) + launch flags. No default until chosen.

### Phase 5 — distribution

COPR for Fedora 44. Document Aurora as untested-then-tested. Clean RPM uninstall.

Stop before: Look-and-Feel art, SDDM theme, GNOME port, bootc image, remix ISO.

## Aurora vs this project

Aurora is a Fedora Kinoite image: silent updates, NVIDIA variants, Flatpak+brew policy, VS Code/devcontainers on DX. It does not do one-palette retint (and its theme docs warn against System Settings theme installs because `/usr` is read-only). It does not do install-then-set-default. It does not treat Claude/Codex/Grok as a first-class default agent.

Gesso is the missing last mile. Aurora can be a later host. It is not a competitor to copy.

## Success criteria

- On Fedora KDE 44: `dnf install gesso-plasma` then one Setup window can change the palette and the default browser.
- Uninstall does not brick Plasma.
- No Hyprland, no custom panel, no ISO.
- The same CLI works headless (theme set, default set) for tests and for people who skip the GUI.

## Out of scope until the above is true

GNOME, COSMIC, Hyprland, a distro, a Universal Blue image, theming GNOME Shell, replacing Discover, clipboard managers, hardware quirks, audio DSP, snapshot/boot story.
