## VS Code theme validation now precedes desktop changes

- **WHAT:** `bin/gesso-theme-set` preflights native and Flatpak VS Code settings before writing the live Plasma colorscheme or applying Plasma. First-time VS Code backups remain staged until all targets validate and the theme reaches VS Code publication. Added `test/cli.d/theme-failure-test.sh` for invalid native settings and valid native followed by invalid Flatpak settings.
- **WHY:** The former merge location ran after Plasma apply, so invalid settings could retint the desktop while disk state rolled back. The merge helper also persisted the first target's baseline before a later target failed.
- **HOW:** Reused `gesso-vscode-colors merge` to stage settings and temporary backup candidates. Failure cleanup removes staged targets/candidates; a publication flag keeps preflight failures from touching the live color file. Existing permanent backups still feed the helper unchanged.
- **IMPACT:** Invalid VS Code settings fail before Plasma, Konsole, or theme state changes, and no backup is left by partial validation. Verified with the new focused test and `test/cli.d/theme-test.sh`; `bash -n` and `git diff --check` also passed. Shared worktree has unrelated setup and arguments-test edits from concurrent work; left untouched.
