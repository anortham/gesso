## Whole-project review of Gesso v1 (read-only)

### WHAT
Read every `bin/gesso-*`, the Setup app, templates, catalogs, spec, docs, and tests. `./test/all` is green (96 ok). Checked outside assumptions with `dnf repoquery` and `mise registry` on this Fedora 44 host.

### Findings that block COPR
- `mise` is not a Fedora package. `dnf install -y mise` in `gesso-default-agent` fails, and `gesso-agents` `Requires: mise` cannot resolve.
- `qt6-qtquickcontrols2-devel` does not exist in Fedora 44. The spec `BuildRequires` fails. `qt6-qtdeclarative-devel` covers QuickControls2.
- The Kirigami Setup app has never been compiled. Devel packages are not on this host either.

### Incomplete features
- `gesso default editor` only writes a Gesso state file. Nothing reads it. No mime or `$EDITOR` change.
- VS Code merge reads `~/.config/Code/User`, but Gesso only installs VS Code as a Flatpak, whose config is under `~/.var/app/com.visualstudio.code/`.
- Flathub on stock Fedora is `filtered`. Chrome, Brave, Edge, Zed, Ghostty Flatpak installs fail until the user enables full Flathub.
- Only one theme. No light theme, no wallpaper support. Ghostty and Foot are in the catalog but not in the theme engine.
- `theme restore` does not clear `theme.name`, Konsole default profile, or GTK prefer-dark. Its Python uses strict JSON while `theme set` accepts JSONC.
- Setup Agents page Launch opens Konsole for `gesso agent` even when no default is set. Window exits at once.
- Setup pages call dozens of subprocesses synchronously on each tab switch. No list/JSON command exists.
- Router help is hardcoded. Metadata keys other than `hidden` are documented but unused.
- No CI workflow.

### IMPACT
"v1 complete aside from COPR publish" in AGENTS.md overstates. Two spec problems plus the unbuilt GUI would fail the first COPR build.
